# 凌矩共享采集站 V0.1

原生微信小程序模拟体验。包含商家端、个人采集员端和单独的凌矩模拟运营工作台。三处示例站点分别演示文具分拣、周转盒装配、仿真花束整理。任务、图片、凭证、设备码和金额均为虚构。

[查看新版微信模拟器截图](evidence/v0.1-interface-refresh.png)

## 用微信开发者工具打开

1. 检出 Draft PR 分支 `codex/wechat-mock-v0.1`。打开微信开发者工具，选择「小程序 → 导入项目」，项目目录选 **`miniapp/apps/wechat/`**。这个目录内有 `project.config.json`。
2. 登录有权限的开发者微信，导入时填自己的小程序 AppID，后端服务选「不使用云服务」。仓库的 `touristappid` 是占位值。本机已用有权限的 AppID 完成桌面模拟器编译与操作验证。模拟器通过后可点「预览」并扫码。若工具写入 `project.config.json`，请把 AppID 变更留在本机。AppSecret 和上传密钥无需提供。
3. 点击「编译」。首次进入从「我是商家」或「我是采集员」进入，之后自动记住身份。用页面右上角「切换身份」回到选择页。
4. 打开「编译模式」下拉菜单，选「凌矩模拟运营」。若工具没有自动列出，手动添加自定义编译模式，启动页面填 `pages/ops/index`，启动参数填 `mode=mock-ops`。从运营页打开商家端或采集员端后，可用模拟器左上角返回运营页。也可用「用户入口」编译模式回到双入口。
5. 选择页底部的「重置演示数据」会清除本机模拟订单、身份、时钟、收益和审计。桌面模拟器与手机各自保存本机数据。

本地编译和扫码预览均在开发者工具内进行。工具的安装入口见 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)。

## 三个演示剧本

每个剧本开始前可先重置。初始模拟时间为 **2026-11-09 08:00（北京时间）**，使用页面的时钟按钮推进。

### 1. 商家从申请到开放和临时暂停

1. 「我是商家」进入「我的演示门店」，点「开始申请」。保留预填的虚构资料，点选门头、室内、设备位置三个照片占位，提交入驻申请。
2. 切到「凌矩模拟运营」编译模式，在「场地」对申请点「模拟通过」，输入模拟审核依据，然后点「登记设备安装」。
3. 由运营页打开商家端，点「确认模拟设备到位」。在「开放时间」选周一，输入 `09:00-12:00, 14:00-18:00` 并保存。
4. 去采集员端，确认新门店出现，预约当天 09:00–10:00。回到同一商家的「开放时间」点「暂停当日」。采集员在「消息」看到变更，在订单中选「无责取消」或换到其他站点改约。周模板保留。

### 2. 预约、采集、归还与分账

1. 采集员 A 进入松墨文具，读图文 SOP，预约当天 09:00–10:00。切到采集员 B 再查看同一设备，最早可预约 10:30。切回 A，打开原订单。
2. 点「模拟开始前往」和「时钟到预约开始」，签到并自助领机。点「时钟到预约结束」，然后「提交归还并模拟上传」。此时订单显示「已提交归还」，采集员收益为待审核，商家场地账目尚未确认。
3. 运营「设备订单」点「模拟核验归还」，输入 `模拟在箱且设备可用`。商家端切到「松墨文具（虚构）」查场地收益，出现一笔待结算，金额待协议确认。
4. 运营「审核」点「录入模拟QA」，输入 `45 / 末段遮挡，请调整视角`。A 的订单显示有效 45 分钟、75%，当月确认虚构报酬 ¥22.50。A 可提出复核，运营输入 `5 / 模拟复查新增5分钟`，原收入保留，补充账目计入下一期。

### 3. 故障白跑、无责取消与补贴申诉

1. A 预约松墨文具当天 09:00–10:00，点「模拟开始前往」，提交模拟设备故障及照片占位。可先为 B 预约同设备 10:30–11:30，保留 B 未出发状态。
2. 运营「设备订单 → 待核查异常」点「核实故障并暂停」，输入模拟故障依据。A 和 B 在站内收到通知。A 在订单无责取消，再「提交模拟凭证并申请」，选择模拟行程凭证。B 可无责取消或改约，未出发时无补贴申请入口。
3. 运营「审核 → 交通补贴」拒绝 A 的模拟申请并填写理由。A 在原订单补充凭证并申诉。运营复核通过后，A 的「收益」单独列出 **待发放补贴**。用「时钟审计」可查看核查记录，设备修复后用「模拟核验可用并复开」。

## 验证

[验收结果及离线编译截图](evidence/README.md)

从仓库根目录运行以下命令，Node.js 版本建议 20 或以上。

```powershell
node --test miniapp/apps/wechat/tests/*.test.cjs
```

在临时目录安装微信编译器封装后，可复跑 WXML 和 WXSS 的离线编译。命令只使用本地文件。

```powershell
$lingjuQa = Join-Path ([IO.Path]::GetTempPath()) 'lingju-miniapp-compiler'
npm install --prefix $lingjuQa miniprogram-compiler@0.2.3
$env:LINGJU_COMPILER = Join-Path $lingjuQa 'node_modules/miniprogram-compiler'
node miniapp/apps/wechat/tests/compile.cjs
```

## 体验边界

- 预约提交串行读取本机最新状态并校验、写入一次。两位采集员是同一设备内的演示身份，跨手机并发和同步需要未来的服务端。
- 开放时间按北京时区和同日半小时预约档位计算。模拟时钟推进才产生提醒和逾期告警。微信订阅授权和推送暂未接入。
- 运营入口通过编译参数隔离，仅适用于调试。真实角色鉴权、视频上传、设备可信归还、上游 QA、支付和正式结算均待后续接入。
- 个人小时单价、固定补贴和时长参数为演示值。场地账目只确认「待结算」笔数，商家费率、到账和打款日待正式协议确定。
- 首版任务取自三个模拟 SOP 模板。运营可暂停或开放任务新预约，场地照片和出行证据使用预设占位。
