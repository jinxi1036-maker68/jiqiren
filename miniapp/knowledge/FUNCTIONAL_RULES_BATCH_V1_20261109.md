## 一、先锁住不能改变的核心规则（已由Owner确认）

1. 只有两个面向用户的入口：「我是商家」「我是个人采集员」；凌矩内部运营后台不算第三种面向公众的经营方。
2. 商家负责授权场地、申请部署、安排开放时间；不负责逐单发放/回收设备，不替凌矩承担设备技术维修及无据补贴。
3. 个人采集员查看真实合法的任务、图文SOP、报酬条件和开放时段，自主预约、自助密码箱取机归还。
4. 同一设备多人可分时预约，不能重叠，相邻已确认预约至少间隔30分钟；当日任务不得跨夜，采集结束至少早于门店关闭15分钟。
5. 采集员提交归还仅成为「已提交归还」，必须另有可信凭证核实后才是「归还完成」。商家场地收益仅在真实采集完成且归还经核验后确认，个人上游QA结论不反向扣减正常场地收益。
6. 个人正常报酬原则上按月结算，按有权上游认可的实际有效采集时长确认；未审核数据保留待审并在完成审核后跨期结算，争议部分不冻结其他已确认收入；结算受合同及法律约束。
7. 采集员设备故障/异常白跑补贴采用固定金额，由授权凌矩运营负责人配置；未出发无补贴、已出发或到店仍需核实才可申请，原则上每笔受影响订单一次；批准≠实际付款，与普通采集收入统一结算并独立列示。
8. 超时与归还处分：首次轻微超时≤15分钟、未影响下一单，警告扣0分；本人原因超时>15分钟或90天内再次无故超时，核实后扣2分；本人原因造成下一位采集员无法正常采集，核实后扣5分；同一事件最高档不叠加。非本人原因免责。
9. 信誉初始100分，连续30天无经核实本人违规恢复1分，最高100分；同类违规滚动90天统计。80～100正常接单、60～79仅预警、低于60暂停新预约并在48小时内人工审核；既有预约不自动取消。
10. QA争议、补贴申诉、信誉扣分申诉均须保留证据与决定记录；不可把演示或自报数据变成已核实事实。

## 二、统一的数据实体与状态（工作默认）

**核心实体**：用户/角色、商家/场地、入驻申请、站点、设备、密码箱、开放时段、任务模板及上游授权、预约订单、执行事件、设备异常、归还验证、上游QA结果/复核、信誉事件、补贴申请、结算批次与账目、消息/送达日志、运营工单与操作审计。每条记录有不可复用ID、创建/更新时刻、操作来源和版本号。

**商家入驻状态**：草稿 → 待审核 →（需要补资料→重新提交）/暂不通过/审核通过 → 待安排部署 → 待商家确认设备到位 → 待设置开放时间 → 已开放；设备与上游授权不足时不向采集员开放真实任务。商家单日暂停仅影响指定场地/设备/时间，不覆盖整周计划。

**预约状态**：待确认（仅界面选择，不算实际占位）→ 已确认 → 前往中 → 已到店 → 采集中 → 等待归还验证 → 已完成；并行的异常/取消分支为：待处理、无责取消、采集员主动取消、疑似爽约、设备异常、归还异常、已取消。状态转换必须校验合法来源，不允许简单更改文字绕过设备占用锁定。

**归还状态**：未归还、已提交归还、核验中、归还完成、异常待处理。照片、手动点击、箱门闭合各只是一类线索，单项线索未必能证明正确设备已在箱内且可用。真正归还完成须有权限明确的可信核验，证据不足就保持核验中。

**收入的两种独立维度**：质量维度（预计/待QA/已确认有效/部分争议/QA不通过）与财务维度（待核算/待结算/待打款/已付款/付款失败）。不得把「审核完成」当「到账」；所有账目有订单和金额规则版本快照。

## 三、商家端完整交互（本节未确认字段均为工作默认）

1. 首页按未入驻/审核中/等待安装/已开放分别给出下一操作；用户可切换身份，不可跨角色查看他人订单。
2. 申请字段沿用店名、地址、经营类型、联系人、联系电话与场景照片。第一版演示可设置门头、室内、设备预置位置三类示例图片；真实必填与身份证明依合法协议另定。
3. 运营核查场地权利、设备存放条件、是否允许合法采集与拍摄、网络/电源/安全；不因提交照片即自动审核通过。
4. 周计划与单日例外采用“周模板+日期覆盖”的计算逻辑；临时关店仅停止受影响范围的新预约，已有订单须通知并支持无责取消/合规改约；已经开始采集或已出发的订单交运营逐单处理，不默默删除或自动赔偿。
5. 日程展示每台设备所有确认时段及30分钟缓冲；商家只查看与自己站点相关的必要时间和状态，原则上不展示个人采集员多余身份资料。
6. 场地收益按自然月查看待核验、待结算、待打款、已到账，逐笔关联完成采集与设备已核验归还的订单；场地收入单价和计费单位由实际协议确定，**20元仅示例**；付款日期尚无权拍板。
7. 商家异常入口可申报临时关店、现场安全风险与设备问题，后续由凌矩运营接管，不让商家承担密码交接或日常追还。

## 四、采集员端完整交互（本节未确认字段均为工作默认）

1. 首页优先用**列表**展示附近可接单的场地/任务，同时提供城市/区域/日期/时段筛选及按距离/开工时间排序。定位是自愿权限，拒绝定位仍可手动选城市和搜索，不可伪造精确定位。
2. 任务详情必须有：合法场景及限制、图文SOP、安全提示、示例动作、实际报酬口径、可预约时段与最短/最长参数、设备信息、需要的完成及归还步骤。真实单价及最小/最大时长由上游和凌矩授权配置；演示可用**显著标为虚构**的参数，不能将“2小时示例”变成真实常量。
3. 预约以设备+日期+起止为主键校验：同设备不能交叠，前后至少30分钟，相同用户时间也不得发生不合理重叠；仅限当日且结束时间在关门前15分钟或更早，必须验证商家周计划/单日例外及设备运营状态。
4. 预约提交时应原子检验及占用，冲突返回可解释的失败信息并刷新时段；按钮重复点击要去重。前端临时选择不代表已抢占资源。
5. 成功预约后展示订单详情、SOP和取机说明。实际密码须采用授权有效期、最小权限和操作日志，演示仅显示虚构数字；取消、故障或失效应撤销相关授权。
6. 出发和签到需记录时间及来源；未获得可验证的签到证据时不能单凭按钮认定已到店、已开始有效采集或符合交通补贴。
7. 预约开始前24小时、2小时和30分钟提醒；短期下单仅排未来的提醒。开始后15分钟未签到提醒，30分钟标记疑似爽约并交凌矩核实，不直接处罚；如原预约仍有效且设备空闲可继续，原结束时间不自动顺延。
8. 预约结束前15分钟提醒准备收尾，结束时提醒停采和归还；超时5分钟再次提醒、15分钟运营告警、30分钟异常未归还待核实。核验归还后抑制尚未发送的催还，后续预约受威胁则暂停该设备新预约并通知下位采集员。
9. 提前至少2小时取消可自由取消；不足2小时需填写理由，归责及扣分仍须核实。取消已确认预约需保留记录、释放资源、停止旧时点提醒。
10. 收益页拆分预计、待QA、已确认与待结算、待打款、已到账；单单展示实际采集时长、有效时长、有效率、拒收原因和申诉。迟到时间不视为有效采集收入。
11. 信誉页展示当前分数、事件记录、30天恢复、90天重复窗口、低分接单权限与申诉；所有低分限制允许查看依据。
12. 设置页包含消息设置、身份切换、隐私授权、人工客服入口；不授权微信订阅消息仍可使用全部核心功能。

## 五、凌矩内部运营后台（批量工作默认）

1. **职责分离**：场地/人员审核、设备与订单运营、QA/申诉、财务对账、权限管理分角色授权；最小权限、敏感操作审计。演示可模拟一名运营账号切换工作台，不能当正式RBAC。
2. **审核队列**：按商家申请、低分接单资格（48小时）、补贴初审（48小时）、补贴复核（72小时）、信誉申诉复核（72小时）、质检复核待办分类；每个工单有负责人、截止时间、历史与升级提醒，逾期不自动批准。
3. **设备工单**：设备故障上报后先核查，由凌矩暂停该设备的新预约，通知受影响预约者；修复、归还、可用性验证通过才能重新开放。设备异常与个人责任独立调查。
4. **结算审核**：不允许单人通过“修改收入记录”制造实际付款；真实环境财务应有审批、付款凭据、对账与失败重试，业务审核人员不等于财务付款人员。
5. **来源追溯**：所有影响收益、扣分、设备状态的决定保留操作人、时间、事件依据、前后状态和申诉历史，演示用虚构姓名及ID，不放客户数据。

## 六、设备、上游质检与数据安全

1. 未经合法合同/客户授权，不允许把客户设备放第三方店铺、多人取用、跨场景采集或传播客户任务素材。无授权时只能展示假任务/假数据。
2. 设备密码按设备/预约/授权窗口最小范围分配，不入库代码常量、GitHub、公开页面或分析日志。未来智能箱传感器需要独立验证“锁闭”“设备在位”“设备正常工作”，不可用其中一个代替另一个。
3. 收集任务只采明确许可的动作/场景；不采无授权顾客、未成年人、敏感区域或第三人隐私；上传路径、加密、授权、存储期限和删除义务正式上线前须完成合规评估。
4. QA来源按上游客户/任务/批次隔离，运营必须验证来源及录入权限；无API时只允许标成有凭据的手动导入，不可宣称自动同步。
5. 质检审核如有部分争议，不应冻结无争议已确认收入；复核成功仅新增可核查有效时长和差额，进入后续结算并保持原QA版本和补录日志。
6. 信誉、QA和应付金额均采用事件式明细与反向更正，不直接覆盖历史，避免申诉及30天信誉恢复时出现重复扣分或重复加分。

## 七、补贴、结算与消息的操作默认

1. 补贴资格：真正白跑且因核实故障/前位未归还设备不可执行；已出发/到店须提供可核实证据，出发前收到故障通知且尚未出发不补。商家默认不承担，前位责任需独立核查。
2. 申请在受影响订单取消后48小时内；凌矩48小时内首审；驳回后72小时内可申诉，凌矩在申诉提交72小时内复核；不自动批准。金额采用生效时固定金额版本，修改只适用于新提交申请，单次原则最多一笔。**金额数值尚未确定**。
3. 已批准补贴与个人月度收入在同一结算机制安排但明细独立；没有其他收入的采集员也要进入结算，不得因零收入丢账；如涉及劳动/服务支付的法定时限，以法律和协议为约束。
4. 通知以站内消息为基础渠道，消息有订单关联和未读数；微信订阅须用户自愿且满足平台模板/次数约束。首次预约成功才可选提示授权，不授权不影响业务。送达失败需可查，不能将“请求发送”记录为“已读”。
5. 消息必须按事件ID去重，过期预约提醒和已核验归还的催还应取消；所有时钟与预约/日期边界采用站点所在时区和带时区记录。
6. **工作默认**：运营告警采用站内待办+负责人未结队列；微信订阅消息不足以承诺每次触达。高风险待办升级规则作为后台配置，不自行确定额外处罚/支付后果。

## 八、第60项 Owner明确确认：低于60分时已有预约如何办

1. 普通信誉扣分造成采集员信誉低于60分，已确认的既有预约**原则上仍可完成**；限制默认仅作用于创建新预约。
2. 如调查涉及设备安全、恶意违规等严重风险，凌矩可先暂停涉及风险的具体任务并核实，保留事件依据、操作人和时间；不得只因一个尚未核实的异常自动取消所有订单。
3. 如须取消既有预约，应及时通知采集员，记录原因与原预约状态，按相关无责改期/取消保护其他受影响用户。
4. 因凌矩主动决定取消任务，**不对该取消行为额外扣采集员信誉分**；若另有经核实的独立违规事件，其已确定处置不因此自动撤销。
5. **默认执行细节**：优先逐单处理受安全风险直接影响的预约；未受影响的订单不批量删除；恢复时重新检查设备和资格，不绕过已有预约。

## 九、剩余规则的批量工作默认及未决门槛

下表各项为**AI_DELEGATED_WORKING_DEFAULT**，没有逐条获得Owner商业批准。首版演示可用标明虚构的配置数据和模拟流程，但生产需要真实合同及授权。

| 事项 | 工作默认 | 是否允许直接按真实业务执行 |
|---|---|---|
| 任务列表 | 列表优先、支持日期/区域筛选，定位拒绝后手选城市 | 仅演示/可调整 |
| 小时选择粒度 | 演示用30分钟单位；最短/最长/设备每日总时长为任务配置项，不设统一真实数值 | 真实参数待上游确认 |
| 预约冲突 | 最终提交原子确认、幂等，防双订 | 技术原则，正式接入时必做 |
| 临时关店 | 停受影响时段新预约、通知已有预约者提供无责取消/改期；已开工订单运营逐单处理 | 人工执行可参考，赔偿待合同 |
| 归还核验 | 必须有独立可信证据；未核实时保持「核验中」而不确认收入 | 真实核验渠道未定 |
| 迟到/爽约 | 超时标记只触发核实；无具体已确认处分标准时不自动扣分 | 不可自动处罚 |
| 质检复核 | 运营核对真实授权来源、记录原结果和差额；缺来源显示待查而不造假 | QA接口/权限未定 |
| 复核超时 | 内部待办提醒负责人，不能自动批准、扣分或发款 | 工作默认可模拟 |
| 商家收入 | 已采集+已核实归还后记入待结算，质检不影响；单价/结算日保留未定 | 真实金额待合同 |
| 个人收入 | 月度核算、未审跨期、正争议和无争议分开；付款需凭证 | 真实支付需协议与合规 |
| 未达接单门槛 | 低于60分只暂停新预约，安全例外可人工停具体既有订单 | 已确认方向，实施待后台 |
| 初步权限 | 超级管理员/运营负责人/审核人员/财务/只读审计工作台区分，权限配置可调整 | 安全设计预案，正式职责待审批 |
| 首版演示 | 只做可点击模拟，不做真实实名、设备控制、真实付款和客户视频 | 仅Issue #24已批准的演示范围 |

**绝不能用默认值代替商业拍板的事项**：

## 十、建议的演示范围、验收剧本和下一步

**第一阶段只有可点击Demo（不改变既有Issue #24批准范围）**：
1. 商家：申请→审核状态→确认安装→设置周计划/临时关店→查看预约排班→收益明细（全部模拟）。
2. 采集员：列表选任务→看图文SOP→在合规余量选择起止→同机第二人只能选剩余时段→模拟开箱→到店→采集→提交归还→模拟可信核验完成→QA质检反馈→收入月度账单。
3. 设备异常：采集员上报故障或逾期未归还→凌矩暂停设备→通知后续预约→无责取消/改约→已出发者申请固定补贴（仅演示金额示例）→审核与申诉→结算状态不等于到账。
4. 信誉：首次≤15分钟逾期警告0分；>15分钟本人责任2分；影响后位采集员5分（不可叠加）；90天统计、30天+1上限100、60分以下停新预约/48小时复核、既有预约不自动取消。
5. 通知：预约开始前24h/2h/30m、开始后15m/30m、结束前15m、结束后5m/15m/30m；模拟订单撤销提醒与已归还后停催还。不要声称微信消息真实发送。

**至少覆盖的验收断言**：
- 单设备同时间双人预约不可能都成功；已有预约前后不足30分钟不能预约。
- 当日预约不能跨日；结束前不足15分钟距关门的订单不许确认。
- 商家审批通过但未完成设备部署与场地开放时，采集员不可下单。
- 「已提交归还」不能变成「归还完成」，也不能触发商家收入确认。
- 取消、改期与设备故障会撤销过期提醒；无关设备订单不受影响。
- 预约迟到不自动续时；真正有效采集小时不等于预约小时。
- 一笔信誉事件最高档只扣一次，非本人原因不扣，申诉纠正与30天恢复不冲破100分。
- 低于60分暂停新预约，已确认订单不自动取消；安全问题有人工逐单停单记录。
- 补贴未出发不产生资格，已出发自报不等于证明；初审与申诉两条时限不同。
