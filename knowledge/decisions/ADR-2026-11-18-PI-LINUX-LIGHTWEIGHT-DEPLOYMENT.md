# 小派派先迁至现有 Linux 小服务器

日期为 2026-11-18。Owner 决定现阶段先部署原电脑上的 Pi 飞书机器人“小派派”，服务器暂不调用浏览器，并在确认后明确停用 `campus-ai-site`、`youyi-trip-h5`、`youyi-wx-share` 三个旧网站服务、保留可恢复文件。此决定调整 11 月 11 日先迁 Hermes 的实施顺序，Hermes 唯一正式数字员工的岗位宪章继续适用。

## 实际执行

- 服务器实测 Alibaba Cloud Linux 3、2vCPU、总内存约 1.83GiB，Node.js 22.22.3。迁移前可用内存约 1189MiB，最终约 1411MiB，最终磁盘可用约 26.5GiB。部署依赖后净增加可用磁盘约 721MiB。
- 停用三个旧网站及 PM2 自启，停止空的 Docker、containerd 和 Docker socket。网站约 1.7GiB 源文件保留。PM2 运行快照、服务配置和经过 tar 列表与 SHA256 检查的恢复配置包保存于服务器私有目录 `/var/lib/lingju-maintenance/pi-20261118/`。
- 清理 DNF、npm 下载缓存、pip 下载缓存和本轮安装临时缓存。旧 pip 不支持 `pip cache` 子命令，改为核对绝对路径后清理 `/root/.cache/pip`。安装依赖、旧网站源码与恢复资料继续保留。
- 同一 Pi 1.5.2、飞书 SDK 1.76.0、pi-memory 0.4.2 通过独立用户 `pi-feishu` 运行，应用位于 `/srv/pi-feishu/app`，工作目录为 `/srv/pi-feishu/workspace`，用户资料位于 `/srv/pi-feishu/home/.pi/agent`。迁移源清单为 190 份文件，含 12 份长期记忆文件、2 个飞书会话映射及原有 CLI 会话。原文件 SHA256 在电脑端核对一致。
- 只适配服务器路径、会话映射、资源配置和当前无浏览器范围。`SessionManager.open` 使用 Linux cwd 覆盖值，保留原 JSONL 内容。会话池目标值调整为 2，服务使用 600MiB 内存软目标、900MiB 硬上限。
- 电脑端 Pi 桥接已停止，登录自启文件移至电脑私有恢复目录。服务器 `pi-feishu.service` 已启用开机启动、失败后自动重启，最终仅一个 Pi 桥接进程。应用实际飞书认证为原“小派派”。

## 验证结果与修正

1. Linux 零模型加载通过，两个原飞书会话均可定位，文件与记忆工具加载成功。原模型 Agnes 3.0 Flash 的两次独立连接检查均取得预期回复，各一次模型响应、零工具调用。
2. 实测一次进程异常退出，systemd 十几秒内拉起新的进程并恢复飞书连接。该测试与 Owner 首条“在吗”发生重叠，中断了该条消息处理。已向 Owner说明，Owner 后来补发并确认收到正常回复。被打断的那次是否已向上游提交请求，现有收据不足以确认。
3. 会话取证发现补发消息曾触发历史 Windows 浏览器任务。实际创建了工作区内一份 66 字节脚本，Ego 与 PowerShell 浏览器命令在 Linux 上失败。该脚本已核对路径后移入私有恢复目录。原始记忆、会话保留。
4. 已加载 `server_policy.ts`，在工具调用入口阻止已知浏览器命令与 Windows 文件路径，并补充当前消息目标的运行说明。6 项零模型断言通过，原 SDK 真实工具调用钩子确认浏览器调用被阻止、普通 shell 可用，扩展加载错误为 0。修正后模型连接检查通过，零工具调用。
5. Owner 已在原飞书单聊确认正常回复。主机整机重启未执行，开机启动项当前已启用。未来模型服务额度与网络状况以实际运行记录为准。
