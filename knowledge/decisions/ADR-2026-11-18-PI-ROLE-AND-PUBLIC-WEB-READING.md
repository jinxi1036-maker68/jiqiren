# 小派派岗位、工作记忆与公开网页读取

Owner 于 2026-11-18 要求参考现有 Hermes 的岗位与公司知识整理小派派的记忆，明确选定“资料研究与日常运营两者兼顾，按我的工作安排自主处理”。Owner 同时希望服务器能访问网页、分析内容和细节，继续保持当前轻量运行范围。

## 岗位与知识

已部署 `hermes/pi_server/identity/` 中的岗位文件与两份工作记忆模板。岗位覆盖公司资料与行业研究、经营分析、文件和获准飞书/API 工作、材料起草、按需技术协助及群内协作。工作方法由小派派根据 Owner 目标自主选择，依现有业务授权和证据要求完成工作。

本轮参考公司岗位宪章、经营纪律、知识索引和发展历史。旧 Pi 记忆的章节元数据以技术故障、用户兴趣和旧环境笔记为主，因此将新的自动装载记忆聚焦当前岗位与业务原则。原 12 份记忆文件已在服务器私有位置保留前像，历史每日文件仍可按日期检索。本轮仅替换 `MEMORY.md` 和 `SCRATCHPAD.md`，增加 `ROLE_BRIEF.md`，未将原记忆正文或账户信息提交仓库。

122 份公司 Markdown/JSON 文件形成约 928KB 的只读知识镜像，来源固定为 main 提交 `9dac85a7881ef6ffcb39ee1d4d98f97d7b6fb275`。Manifest 记录文件 SHA256。入口为 `/srv/pi-feishu/company-knowledge/knowledge/00_START_HERE.md`，Manifest 为 `/srv/pi-feishu/company-knowledge/SNAPSHOT_MANIFEST.json`。镜像中的旧日期和阶段状态分别理解，实时平台数据与 Owner 新决定另取当前来源。

## 网页读取能力

新增 `read_webpage`，使用 Python 3.6 标准库和普通 HTTP GET 读取公开 HTML、文本、JSON/XML。Pi 现有 `typebox` 依赖提供工具 Schema。结果给出来源 URL、抓取时间、HTTP 状态、正文、链接、文本表格数量、哈希和截断信息。

私网与回环地址、保留地址和 URL 内登录凭据会被拒绝，重定向逐跳核对。网络连接固定使用已校验的 IP，TLS 继续核对原域名证书。执行网页 JavaScript、登录数据、图表数值、图片视觉理解和二进制附件解析均不属于本工具的已验证读取范围。动态数据可在未来按实际需要接授权 API、导出文件或经 Owner 批准的其他读取服务。

## 实测与限制

- 8 项零模型检查通过，覆盖公开地址、私网与云元数据地址、凭据 URL、内部重定向、HTML 标题和表格、链接以及读取范围。
- 服务器服务用户实际读取 Example Domain、Python 官方文档及中国政府网，取得 HTTP 200 和可用正文。部分域名在服务器当前网络中无法连通，不能据此声称所有网页均可读取。
- 原 Pi SDK 加载所有扩展，错误数为 0，工具目录出现 `read_webpage`。岗位检查使用 1 次模型响应、0 次工具调用，回答正确指出公司、兼顾岗位、知识路径、网页工具与范围限制。自述中的 Manifest 路径曾不够精确，已将记忆改为完整绝对路径。
- 网页分析检查由原 Pi SDK 自行执行 1 次 `read_webpage`，主模型响应 2 次，取得 Python 文档正文并汇报来源及范围。定点文件读取记录确认新 `MEMORY.md` 实际被读取 1 次。本轮 Codex 验证合计 3 次模型响应，重试已关闭，未发送额外飞书测试消息。
- 已核对原飞书会话为空闲状态后重载一次常驻服务，飞书重新上线。原服务仍为同一小派派应用、单进程、独立 Linux 用户，当前浏览器命令限制继续生效。

本轮本地 Firecrawl CLI 的一次公开页面读取确认该阅读路线可用。服务器实现使用直接 HTTP，当前没有配置 Firecrawl 账号凭据。
