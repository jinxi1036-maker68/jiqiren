# 小派派统一岗位记忆与共享技能

日期：2026-11-21

## Owner目标与问题

Owner要求同一个小派派在本人单聊、同事私聊和群聊中保持共同的岗位能力，同时不能让每个聊天形成互不相认的技能孤岛。实际截图证明“图片理解”统一记忆已能被群聊使用，但群聊询问 `ego-sop` 时只复述了相似流程，没有承认服务器上已经存在的正式技能。

根因是两类内容此前混在一起：`shared-memory.json`适合保存简明能力说明、长期规则、流程与正式待办；真实技能的完整方法、格式和避坑记录仍只在服务器技能目录，受限共享会话没有加载它。把技能再概括成一条记忆不能等同于发布技能。

## 决定与实现

- 保留按聊天隔离的短期对话历史，不建立所有人的完整聊天汇总，也不把个人隐私扩散到其他入口。
- 新增`shared-skills.json`，保存负责人明确批准发布的服务器技能只读快照、来源SHA256和更新时间。同名再次发布为更新快照。
- 原Owner单聊增加`publish_shared_skill`；只有Owner明确要求已有技能供所有入口使用时才发布。长期规则、流程和正式待办继续使用`remember_shared`。
- 发布前限制技能名称和文件大小，拒绝路径穿越及疑似密码、Cookie、API Key或私钥内容；共享技能总数和上下文大小均有限制。
- 所有共享聊天加载已发布的技能正文和`LESSONS.md`，承认它是小派派正式技能并按方法工作。首个发布`ego-sop`，因为Owner已在飞书明确要求它成为所有聊天的长期公共能力。
- 共享技能只提供方法，不扩大权限。共享入口仍不能读取或修改服务器文件、执行命令、访问灵生私有工具、写共享记忆或执行技能中的自修改要求。当前飞书图片已由桥接直接传给模型，旧技能中要求提供服务器图片路径的历史说明不适用于共享入口。

## 验收与真实边界

- 本地测试覆盖持久化快照、同名更新、真实上下文生成、路径穿越和疑似凭据阻断、Owner发布工具。
- 服务器候选目录使用原Pi依赖执行共享聊天、统一记忆和共享技能共10项测试；全部通过。另用生产`ego-sop`文件生成候选快照，核对技能名、六步SOP要求、飞书图片直接输入覆盖说明及来源SHA256。
- 完成部署后再核对systemd服务、快照权限、已发布名称、Owner工具注册和飞书重连。代码或快照验证失败时恢复本轮私有前像。
- 这些检查证明共享入口获得`ego-sop`方法，不等于任意外部人员获得公司私有数据或后台工具，也不等于真实群聊回答已经验收；实际群聊仍需用一条非敏感问题确认回复。
