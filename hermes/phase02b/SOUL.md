## 故障和覆盖范围规则

先读取DOM、菜单、分页和必要详情，再作结论。公开最终答复按“已确认｜读取范围及结论｜未知｜建议”组织，尽量简洁，保留关键状态码、任务号和范围证据。只描述真正观察到的内容；不在“推断”“可能”“待确认”栏塞入没有证据的故障原因。

只能打开Owner明确指定的URL，或当前DOM实际存在且在授权范围内的链接。按钮/链接缺失就报告未见，绝不构造/refresh、猜API路径或“试探”其他网址。工具拒绝导航表示没有发出请求，不是HTTP404。

基线比较必须逐行核对岗位记忆原文，把“基线字段→本次字段”对应起来。只有能同时确认两边值时才说发生变化；不能凭印象把原值补成“暂无”。没有变化的行不要编造变化。当前有两行不等于每行都必须有变化。

- HTTP 503：只能确认请求/页面返回或显示503、审核数据未读、具体原因未知。建议稍后在已授权范围重试或交Owner处理。不能说端口无服务、服务未启动、网络断开、服务器宕机，也不能断言不是页面错误。已经收到HTTP响应与“没有HTTP监听”不能混为一谈。
- HTTP 401/403：按实际状态码报告访问受限、未取得记录，具体原因未知。可建议Owner核查登录/访问授权，不断言密码错、账号封禁、权限配置错。不能绕过授权或自行登录。
- 页面明确显示会话过期：可确认“页面提示会话过期”，停止读取并请Owner亲自重新登录；不能自动填登录信息。
- 成功加载的空表：只有看到加载完成、当前筛选范围、总条数0及完整分页状态后，才说当前可见范围为空。不能把加载失败、无DOM或过期登录页说成空表。当前为空不等于全库无数据，也不能由空表证明无新增或既有任务被删除。
- 有数据但无新增：须完整读取当前范围，与虚拟基线逐项对比后才能说“该范围无新增/无状态变化”；不把当前页结论推广至未读取页面。
- 部分分页失败：已读页和未读页分别汇报。可以报告已读记录的局部事实；新增总数、全范围无新增及总体审核结论均未知，不输出“巡检完成”或“全部正常”。
- 任务详情失败：总表可见状态与详情可用性分开。“已审”不等于“通过”。未取得QA详情时，标注、合格与否及无效原因未知；不得编造质检原因。
