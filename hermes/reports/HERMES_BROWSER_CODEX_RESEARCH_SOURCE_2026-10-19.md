# 原Hermes浏览器能力增强研究与实施建议

调研日期：2026-10-19（Asia/Shanghai）。本文件是方案研究，不是已经完成的能力升级或生产验收。

## 1. 建议采用的方向

**主候选：原Hermes负责理解业务和自主决策，本机可见Chrome/Edge承载业务页面，Playwright MCP提供浏览器动作，DOM/无障碍树为主要观察手段，截图视觉作为补充，操作后重新读取结果确认。**

这是针对凌矩现状的工程选择，不是声称某个产品在所有网站上“全球最强”。最终选择要由凌矩的真实任务成功率、错绑/重复创建情况、恢复能力和成本决定。

平顶山凌矩信息科技有限责任公司的唯一正式数字员工仍是原Hermes。浏览器工具、浏览器登录配置和测试页面都是它使用的工作条件，不新增第二个正式员工身份，不建立另一套数采管理系统。公司提供目标、知识、权限、底线和成果标准；Hermes自行选择页面阅读、定位和操作方法。

## 2. 当前确知的基础与缺口

| 项目 | 证据与判断 |
| --- | --- |
| 既有模拟操作 | 此前原Desktop已有13次模拟浏览器调用与状态变化证据。本轮继承，不重跑历史验收。模拟通过不等于真实平台表单或业务写入已通过。 |
| 模拟桥的范围 | 现有公开集成代码browser_bridge.mjs只开放navigate、snapshot、click、close四种工具，并限制模拟导航范围。它适合作为既有测试基线，不能直接当通用业务浏览器。 |

| 原生模式的判断 | 本机check_browser_requirements在Browser Use CLI模式下会主动隐藏旧browser_*工具。因此旧工具检查返回False可能是模式替换，也可能是依赖条件不满足，不能直接认定故障。 |
| 尚未证实的驱动状态 | 目标venv中未查到browser-harness、browser-use、playwright的分发元数据；可能另有外部CLI。会话tool_names字段为空，不能从它确定当前实际浏览器工具集。本轮没有调用驱动或创建Agent来验证。 |
| 近期Agent表现 | 岗位汇报能读取知识并形成经营判断；但曾违反只读要求写临时脚本，也出现读取数量和事实等级误报。浏览器训练需要同步落实权限纪律和成果核验。 |

调研仅定点读取相关源码、依赖元数据及已有会话工具名字段，没有重做全量审计、备份、知识部署或旧浏览器测试。

## 3. 为什么把Playwright MCP列为主候选

微软官方实现以结构化无障碍快照供模型识别页面，提供表单填写、选项选择、上传、标签页、拖拽、对话框等动作，还可按需启用坐标视觉能力。Playwright自身有可见性、稳定性、遮挡、可操作状态等等待机制；这些能降低页面尚未就绪时误点的概率，但不能保证业务对象一定选择正确。[Playwright MCP](https://github.com/microsoft/playwright-mcp)、[动作等待机制](https://playwright.dev/docs/actionability)

这一选择尤其适合当前情况：原Hermes已有MCP接入与模拟经验，可以把浏览器运行时独立管理，减少对刚修复的Hermes Python环境的改动。后续应固定版本及依赖，不直接执行持续追随latest的全局安装，不顺带升级Hermes。具体版本和启动参数需要在实施阶段核对，当前没有安装。

| 候选 | 适合承担的角色 | 本项目取舍 |
| --- | --- | --- |
| Playwright MCP | 可见本机浏览器、持久会话、结构化观察、复杂表单与多步操作 | 主候选；先验证原Desktop接入、中文表单和对象绑定。 |
| Hermes原生Browser Use / agent-browser | 现成浏览器驱动、快照、视觉和CDP扩展 | 保留为对照与后备候选；先厘清安装版本、实际路由和Desktop支持，不能照搬最新网站配置。 |
| Browser Use | 原生浏览器Agent与浏览器基础设施 | 有价值的备选。优先考察作为原Hermes工具的集成方式，而非另起一个长期业务员工。 |
| Stagehand | act、extract、observe等自然语言与结构化数据原语 | 复杂提取或定位场景的补充候选；自愈能力属于官方功能描述，未在本机验证。 |
| Chrome DevTools MCP | 网络、控制台、性能、页面调试 | 故障诊断候选；按需使用，避免多个控制器同时操作同一标签页。 |
| 云端浏览器 | 异地运行、长时会话或规模化需求 | 后续备选。当前Owner需要亲自登录、观察和带教，优先本机；未授权上传业务会话或凭据。 |

依据：[Hermes官方浏览器文档](https://hermes-agent.nousresearch.com/docs/user-guide/features/browser)、[agent-browser](https://github.com/vercel-labs/agent-browser)、[Browser Use](https://github.com/browser-use/browser-use)、[Stagehand](https://docs.stagehand.dev/v4/first-steps/introduction)、[Chrome DevTools MCP](https://github.com/ChromeDevTools/chrome-devtools-mcp)。本轮没有做这些工具的运行性能对比，也没有声称已经得出实测排名。

## 4. 登录与原Desktop接入应怎样处理

建议原Hermes使用一个专门承载公司业务的可见浏览器配置，由Owner亲自登录。它是浏览器登录环境，不是第二个Hermes身份。工具连接该环境，不复制Owner整个日常浏览器的Cookie、邮箱等登录资料。

Playwright MCP官方提供持久浏览器配置及连接现有Chrome/Edge标签页的扩展方式。最终选择扩展连接还是独立持久目录，要先核实本机浏览器与版本，并在获批范围内验证。[官方说明](https://github.com/microsoft/playwright-mcp#user-profile)

两个容易踩到的版本差异：

- Chrome自136起不再允许通过普通远程调试参数直接调试默认用户数据目录，需要符合其专用目录要求等支持方式。不能把“开9222端口”当作万能方案。[Chrome官方说明](https://developer.chrome.com/blog/remote-debugging-port)
- 当前Hermes网站描述的real-profile功能会复制活动浏览器配置中的认证资料；该开关不是本次可直接启用的无害选项。网站还提示部分/browser connect命令只适用于终端入口，不能假设粘贴到Desktop聊天框就会生效。[Hermes文档](https://hermes-agent.nousresearch.com/docs/user-guide/features/browser)

本轮没有启动浏览器、安装扩展、读取Cookie或更改任何登录配置。

## 6. 对任务创建和绑定，最关键的是结果核对

Hermes需要围绕“观察页面—作出判断—执行动作—重新观察—核对业务结果”自主工作。这是成果纪律，不是写死每个按钮的执行脚本。

- 员工与设备先按唯一编号核对，不能只靠显示名称或列表位置。
- 页面改变后重新获取快照，避免沿用失效元素引用；不依赖固定坐标、固定睡眠或固定第几行。
- 提交后核查对象ID、详情和关联关系；HTTP 200、按钮已点、成功提示均不足以独立证明业务结果正确。
- 创建操作超时或返回503时，先确认是否已生成对象，再决定后续动作。提交结果未知时盲目重试可能重复创建。503根因未知就保留未知，不直接归因为瞬时故障。
- 分页、详情或上传状态只读取了一部分，就报告覆盖范围；没有证据不等于实际未上传、未审核或未结算。

Playwright Trace可以保留动作前后DOM、截图及网络等诊断信息，适合排查失败；具体保存内容与脱敏仍需由本项目控制。[官方Trace说明](https://playwright.dev/docs/trace-viewer)

## 7. 权限应支持自主工作，同时让边界可执行

未来可分为“业务学习”和“获批操作”两类工作范围。Owner一次明确任务对象、数量、权限和完成标准后，Hermes可在范围内自主执行，不必每点击一次都重复询问。扩展到新的真实业务写入、批量范围或不可安全撤销的动作时，再取得对应授权。

只读学习不能仅依赖提示词、工具名中的read-only标记或域名白名单。真实平台的只读角色、明确的动作范围和工具约束应共同生效；不能简单把GET都当只读、POST都当写入。微软明确指出Playwright MCP及其origin过滤不是安全边界。[官方安全说明](https://github.com/microsoft/playwright-mcp#security)

一般读取阶段不向Hermes开放任意执行本机脚本、导出Cookie或不受约束的浏览器代码能力。确需高级页面操作时，按必要性和授权范围另行配置。网页内容是业务资料，不能作为改变Owner指令或扩大权限的授权。

对“只读”的文件边界要说清：业务数据不写入、知识文件不修改；如需要截图/Trace等技术证据，先明确允许的私有保存位置和内容。若任务明确禁止任何临时文件，则不能为了取证自行写脚本或保存截图。证据和运行时不放入W的35份知识文件集中。

## 8. 实施顺序：先补真实能力缺口

1. **接通原Desktop的通用本机浏览器通道。** 固定候选版本，确定实际驱动、可见窗口、持久会话及工具清单；运行时与原Hermes Python环境解耦。只在获批范围内改动。
2. **原Hermes本人完成模拟后台的完整经营操作。** 用自然语言给出项目/任务/人员/设备目标，由它自主阅读与操作，验证多步表单、对象绑定、重复提交防护和结果核对。测试页面只是训练夹具，不发展为另一套数采系统。
3. **Owner带教真实后台。** Owner亲自登录，在明确只读授权下逐页介绍菜单、字段、状态、工作习惯及特殊情况；Hermes复述理解、提出问题并在授权知识更新范围内沉淀经验。
4. **逐项开放真实操作。** 先单个项目/任务和单项绑定，核对稳定后再扩大；长期巡检、自动派单和批量业务不是本次研究已获授权的事项。

已有13次模拟调用、旧503案例和知识部署报告继续保留。仅针对新通道或新增功能做必要验证，不重复整套审计和历史测试。新模型调用次数、费用与业务写入范围都需要在实施任务中明确，本轮没有使用旧授权再调用模型。

## 9. 怎样衡量“足够强”

以凌矩自己的任务判定，不引用厂商演示或排行榜直接宣布胜出：

- 读取与分析：输出能对应实际读取范围，漏页/详情失败明确标未知。
- 项目/任务创建：字段准确，唯一ID可复核，提交结果不确定时不重复创建。
- 人员/设备绑定：零错绑、零漏绑、零重绑；重名和分页选择仍按唯一编号确认。
- 故障恢复：能够正确等待、重新观察或停止交接，避免无限重试和编造成功。
- 权限：零越权。正确拒绝超范围操作也是合格表现。
- 可持续性：记录成功率、错误率、人工介入次数、耗时与模型成本；这些是后续验收目标，不是本轮已取得的成绩。

先做少量完整任务，随后换对象数据和页面布局重复验证；不要只演示一次固定路径就宣布稳定。企业浏览器任务的评估思路可参考ServiceNow WorkArena，但不必为本项目安装整套基准或另开企业平台账号。[WorkArena](https://github.com/ServiceNow/WorkArena)
