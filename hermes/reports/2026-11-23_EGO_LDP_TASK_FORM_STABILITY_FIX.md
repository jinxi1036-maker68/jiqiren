# 2026-11-23｜Hermes Ego 灵生任务表单稳定性修复

## 结论

- **已证实：Ego 核心通道在线。** 本机 `ego-browser` 可执行，正式公司浏览资料中的灵生页面可读取。
- **已证实：项目和设备选择可稳定完成。** 在不提交业务数据的表单验证中，使用 Ego 高层语义点击选择项目、选择设备，页面选中值回读一致，随后关闭弹窗。
- **已证实：失败主要来自 Hermes 的旧操作策略，不是 Ego 整体不可用。** 故障会话持续约 963 秒，产生 15 次模型请求、154 次工具调用；同一目标建立多个 TaskSpace，并混用 React 值注入、DOM 点击、CDP 坐标点击及重复等待，期间还出现脚本变量未定义。

## 修复

- 新增单空间、语义操作、唯一匹配、逐项回读、提交一次与未知结果不重提的表单工具。
- 新增当前技能覆盖规则，禁止在普通 Ant Design 表单使用坐标点击、直接 DOM click、native value setter、硬编码选项序号和重试风暴。
- 本机正式技能只部署上述浏览器机械能力，不改 Hermes 身份、记忆、业务判断、模型、凭据或公司知识。

## 验收边界

- 本轮没有创建真实任务，没有向 Hermes 发送模型消息。
- 正式公司浏览资料中的零写入 dry-run 已完成并在结束空间后用全新空间复验：两次任务名、项目、设备、采集时长、交付时长、SOP、开放标注七项预检均全部为 `true`；回执均为 `submittedOnce:false, discarded:true`，关闭弹窗后页面列表未出现验证任务名。
- 本机生产脚本与仓库源文件 SHA256 均为 `6619D111180A3F45728781BB1987EC46A9AD3603094C8C86C5F313B516B2F1A4`。
- 已验证项目/设备选择与读回；完整真实提交只应在 Owner 具体业务授权下执行并以平台列表回读为准。本轮没有以测试名义创建真实任务。
