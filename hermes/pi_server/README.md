# 小派派 Linux 飞书部署

沿用电脑上现有 Pi 1.5.2、飞书 SDK 1.76.0 和 pi-memory 0.4.2。保留小派派原飞书应用身份、会话和记忆，在 Linux 上运行一个桥接进程。初次迁移时按 Owner 要求停用通用浏览器，之后仅增加本文所述的灵生只读工具。

## 文件与运行

- `src/` 为现有飞书桥接源码。恢复会话时向 `SessionManager.open` 传入 Linux 工作目录，保留原 JSONL 会话内容。
- `package-lock.json` 固定依赖。使用 Node.js 22.19.0 及以上版本执行 `npm ci --omit=dev --ignore-scripts`。
- `pi-feishu.service` 使用独立用户 `pi-feishu`，从 `/srv/pi-feishu/app` 启动。用户主目录为 `/srv/pi-feishu/home`，工作目录为 `/srv/pi-feishu/workspace`。
- 运行目录的 `.env`、`home/.pi/agent/` 和 `app/data/` 由私有迁移包提供。其中包含认证、记忆和原会话，仅存 Owner 控制的位置。
- `.env` 中 `PI_CWD=/srv/pi-feishu/workspace`、`MAX_ACTIVE_SESSIONS=2`。会话映射中的文件路径改为 `/srv/pi-feishu/app/data/sessions/`，原会话正文保留。
- 服务器设置暂时排除浏览器相关 Skills 自动装载，保留其原始文件。没有安装浏览器运行时。
- `server_policy.ts` 在 Pi 工具调用入口阻止已知浏览器命令及 Windows 文件路径，提示以当前消息为工作目标。它由服务器 Pi 的 `settings.json` 中 `extensions` 配置加载。

服务设为开机启动和失败后自动恢复，内存软目标 600MiB、硬上限 900MiB。实际可用能力仍取决于模型服务及现有工具依赖。部署前后应通过原飞书单聊验证真实收发。

## 岗位、记忆与公开网页

Owner 随后确定岗位兼顾资料研究、经营分析和日常运营协助，按工作目标自主处理。`identity/ROLE_BRIEF.md` 是岗位文件，`identity/MEMORY.md` 与 `identity/SCRATCHPAD.md` 是本轮部署的工作记忆模板。旧记忆前像保存在服务器私有恢复目录，本轮整理只替换这两份自动装载文件。

公司资料在 `/srv/pi-feishu/company-knowledge/`，Manifest 固定 GitHub 来源提交和 122 份 Markdown/JSON 的 SHA256。资料按任务读取，运行时不会将全部公司历史放入提示词。

`src/web_reader.ts` 注册 `read_webpage`，通过 Python 标准库脚本 `src/web_read.py` 发出普通 HTTP GET 请求，提取正文、链接及文本表格。结果包含来源、时间、HTTP 状态、内容哈希、正文或链接截断标志。逐跳核对公开地址并固定实际连接的 IP，拒绝私网、回环、保留地址和 URL 内的登录凭据。当前图片、二进制附件、需 JavaScript 加载的数据和登录后台应根据实际读取范围报告。工具整体运行超时为 25 秒，单页正文默认最多 12000 字符。

将 `/srv/pi-feishu/app/src/web_reader.ts` 加入服务器 Pi `settings.json` 的 `extensions` 后，在空闲时重载服务。测试命令为 `python hermes/pi_server/test_web_read.py`。2026-11-18 已通过 8 项零模型回归检查、3 个公开站点实读、岗位自述和原 Pi SDK 工具调用分析验证。详细部署结果见公司知识库同日岗位与网页能力决策记录。

网页工具默认尝试用 Mozilla Readability 提取文章。它处理已下载的 HTML，页面表格继续走原有解析，链接、标题和来源回执始终来自原网页。正文提取失败或返回内容过少时自动使用原网页文本。调用时可指定 `text_mode: "page"` 查看正文之外的文字，仍适用原返回长度上限。

随应用一起发布 `readability/`，在该子目录运行 `npm ci --ignore-scripts`。生产依赖固定在独立锁文件。运行 `python -B hermes/pi_server/test_web_read.py` 可核对正文清理、保留表格和失败回退。

飞书桥接根据当前轮的工具回执和模型终止状态生成失败提示。例如，网页只返回空正文且模型返回 HTTP 429 时，会同时说明这两点。运行 `node --test hermes/pi_server/test_pi_reply.js` 可核对错误、成功重试和中断时的回复。

### 服务器灵生后台只读取数

Owner 后续授权小派派直接从服务器查询灵生。方案以服务器单独的浏览器会话保存登录，只为明确授权的飞书单聊提供 `read_livsyn`。平时只有取数服务监听本机 Unix socket。收到请求后，服务启动一个 Chromium 进程组，查询结束关闭浏览器。

- `livsyn/` 包含浏览器进程、私有登录窗口、Unix socket 接收程序和 systemd 服务。部署目录为 `/srv/pi-livsyn/app/`，Playwright Core 由独立锁文件固定，Chrome for Testing **158.0.8127.36** 单独放在 `/srv/pi-livsyn/chrome/`。
- 私有浏览资料位于 `/var/lib/pi-livsyn/profile/`，由独立系统用户保存。负责人通过 SSH 转发窗口亲自登录。登录窗口与取数程序共享文件锁。窗口结束后，登录凭据仍留在该服务器浏览器资料中。
- 取数网络只放行灵生域名的 GET、HEAD、OPTIONS 请求。读取会话禁用服务工作线程和 WebSocket，并忽略页面发起的下载。正式取数服务只接受原 Pi 飞书进程或服务器管理员的本机连接。飞书工具按管理员维护的本机 `livsyn-owner.json` 比对单聊和发送者。原私聊、群聊策略与该绑定独立，群聊和机器人协作会话不装载取数工具。该绑定文件含实际飞书标识，留在服务器。
- 业务页包含采集统计、项目、采集任务、上传、数据集、标注与审核、设备。汇总每次最多 5 页，明细每次最多 2 页。结果包含当前范围、下一页和已读全表标记。报告时间来自页面当前查询范围。明细按允许字段返回，设备 ID 和采集员姓名未列入。
- 验证命令是 `node --test test_livsyn.mjs test_pi_reply.js`。在服务器同版 Pi SDK 的隔离会话中核对单聊装载、群聊隔离和异常回执。浏览器零模型探测用合成页面核对 POST 拦截。

2026-11-18 负责人亲自完成服务器登录。临时窗口关闭后，在服务器验证七个业务页均能取得真实数据，包括统计表 14 条、项目 3 条、采集任务第 2–3 页明细 40 条、上传第 12 页 20 条、数据集第 20 页 20 条、审核及设备各两页 40 条。浏览器读数进程组峰值约 396 MiB，验收结束的空闲时点没有浏览器进程。上述分页范围作为实测记录。

原 Pi 飞书服务在空闲时重载并重新上线。部署校验比对了 3 份原桥接文件和实际启用的 6 份源码。首次飞书任务收到消息，原私聊配置为开放模式，初版工具因缺少私聊白名单未装载。依据 Owner 确认发送的测试消息与服务器会话记录建立独立授权绑定，并重载原服务。群聊和普通私聊的原有接收策略继续生效。

绑定后的首次验收显示工具已装载，模型仍走旧网页路线。原飞书桥接现在对授权单聊中明确指定灵生业务页面的查询先读取实际数据，再将回执和用户任务一起交给 Pi。普通问候照常交给 Pi。查询回执给出分页和统计日期，模型可继续查询及分析。统计事实无法随模型答复交付时，可直接回传网页读到的数值和来源。旧的公开网页与 shell 路线不再用于灵生后台。

最终飞书验收由 Owner 在原单聊发送「查灵生统计」并确认收到。生产会话记录显示原 Pi 启用只读工具，服务器后台查询成功，实际统计日期和两个时长随回执进入模型上下文，模型在一条最终答复中引用了两个时长。回复由桥接补充来源链接。此验收覆盖飞书单聊到服务器取数再到回复的闭环；多页全量和跨模块经营分析以实际查询覆盖范围为准。

改动上线前保存原桥接文件前像。回退时核对最新文件哈希，撤掉本轮新增的本机授权绑定和读工具文件，恢复 `bridge.js`、`piagent.js`、`server_policy.ts` 的原文件，在空闲时重载 Pi，再停用 `pi-livsyn-reader.service`。服务器浏览资料继续按原保护方式保存。

回退本轮岗位或网页变化时，先核对待恢复文件是否与本轮最终哈希一致。依据私有前像逐项恢复记忆、settings 和策略文件，在空闲时重载。若实际工作已更新记忆或配置，应先保留新增内容再决定恢复范围。

## 切换与恢复

先备份并核验电脑 Pi 的程序、模型配置、记忆和会话，完成服务器零模型检查与一次模型连接验证。停止电脑的 Pi 桥接，将其登录自启文件移到私有恢复目录，再启动服务器服务。

需要退回电脑时，先停止并禁用服务器的 `pi-feishu.service`，确认桥接进程结束。将切换后新增的会话和记忆同步回电脑并核对路径，恢复已保留的登录自启文件，再启动原电脑桥接。两端同时接收真实消息会造成重复或分流。

本轮停用的旧网站代码、PM2 启动快照和服务配置保存在服务器原目录及 `/var/lib/lingju-maintenance/pi-20261118/`。恢复网站前根据该目录的原始状态分别启用服务。完整回退资料保存在私有位置，GitHub 仅存脱敏源码和执行结果。
